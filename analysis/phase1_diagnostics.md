Generated by `analysis/assemble.py`. Every table is produced by code in this directory; the prose is hand-written.
`engine.py`, `reporter.py` and `phase1_preregistration.md` were not modified by this analysis.
This revision replaces the first version (241 fills, 39 minutes, Hyperliquid only; see git history).

## Read this first

- **Which data.** The 6,064 primary fills are in `paper_mm2/data_v1/`: after the Phase 1b cutover (Amendment 3) the old
  `paper_mm2/data/` was archived there and `data/` was reset. `data/` is currently empty, so there is nothing from Phase 1b to analyse yet.
- **This is exploratory Phase 1a analysis only.** Amendment 3 excludes the v1 data from Phase 1b statistical analysis; nothing here may be used
  for a Phase 1b decision, and none of it is a registered test. The v1 hold-out (2026-10-12 onward) was never opened and is not read:
  `common.py` drops any row on or after the hold-out start (all v1 rows are on 2026-10-08).
- **Sample.** 2026-10-08 06:43-17:30 UTC (647 min, 127 five-minute blocks). **6,064 rows = 3,973 distinct fill events**: Hyperliquid arm A 3,026
  fills (24 instruments), Binance arm A 866 (15 instruments). Arms B and C re-fill mostly the same prints (B in A 94.6%, C in A 92.5%,
  C in B 97.9%), so arm rows are about 95% overlapping, not independent samples. The sample is one morning-to-afternoon session on a Thursday.
- **Engine under test.** The data was produced by the pre-Amendment-3 (v1) engine: no requote timer (D1), event-time volatility (D2), arm C
  flow filter skipped when the 80th percentile is 0 (D3), queue-depleted events logged without outcomes (D4). The current working-tree engine
  differs; see `phase1b_review.md`.
- CIs are 5-minute block bootstraps (10,000 resamples, seeded). With ~120 blocks they are reasonable, but fills inside a block and across
  instruments in the same block are still correlated.
