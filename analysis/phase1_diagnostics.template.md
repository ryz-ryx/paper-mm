# Phase 1 diagnostics (Phase 1a / v1 data; exploratory, post-hoc)

Generated by `analysis/assemble.py`. Every table is produced by code in this directory; the prose is hand-written.
`engine.py`, `reporter.py` and `phase1_preregistration.md` were not modified by this analysis.
This revision replaces the first version (241 fills, 39 minutes, Hyperliquid only; see git history).

## Read this first

- **Which data.** The 6,064 primary fills are in `paper_mm2/data_v1/`: after the Phase 1b cutover (Amendment 3) the old
  `paper_mm2/data/` was archived there and `data/` was reset. `data/` is currently empty, so there is nothing from Phase 1b to analyse yet.
- **This is exploratory Phase 1a analysis only.** Amendment 3 excludes the v1 data from Phase 1b statistical analysis; nothing here may be used
  for a Phase 1b decision, and none of it is a registered test. The v1 hold-out (2026-10-12 onward) was never opened and is not read:
  `common.py` drops any row on or after the hold-out start (all v1 rows are on 2026-10-08).
- **Sample.** 2026-10-08 06:43-17:30 UTC (647 min, 127 five-minute blocks). **6,064 rows = 3,973 distinct fill events**: Hyperliquid arm A 3,026
  fills (24 instruments), Binance arm A 866 (15 instruments). Arms B and C re-fill mostly the same prints (B in A 94.6%, C in A 92.5%,
  C in B 97.9%), so arm rows are about 95% overlapping, not independent samples. The sample is one morning-to-afternoon session on a Thursday.
- **Engine under test.** The data was produced by the pre-Amendment-3 (v1) engine: no requote timer (D1), event-time volatility (D2), arm C
  flow filter skipped when the 80th percentile is 0 (D3), queue-depleted events logged without outcomes (D4). The current working-tree engine
  differs; see `phase1b_review.md`.
- CIs are 5-minute block bootstraps (10,000 resamples, seeded). With ~120 blocks they are reasonable, but fills inside a block and across
  instruments in the same block are still correlated.

## Deviations and limitations (status after the Phase 1b engine, see `phase1b_review.md`)

| ID | Finding in the v1 data | Phase 1b status |
|---|---|---|
| D1 | Requote is evaluated only on book updates: Hyperliquid quote age at fill median 2.9 s (max 6.2 s), 77% older than 1.5 s. | Timer loop added (polls every 250 ms, so 1.0-1.25 s). Not yet measurable. |
| D2 | `realised_vol_10s` used consecutive book updates: 99.6% zeros on Hyperliquid, 22-29% on Binance. | Redefined as 1-second-sampled returns. |
| D3 | Arm C cancel-on-flow skipped when the 80th percentile was 0; only 4.5% of arm C fills had non-zero adverse flow on HL, so C ~ B (916 vs 947 fills). | Changed: cancel on any adverse flow when the percentile is 0 (and the percentile is now sampled on book updates too). |
| D4 | Queue-depleted events carry no outcomes. | Outcomes now logged. |
| D5 | Arms are ~95% overlapping, not independent. | Not addressed. |
| D6 | Reporter dates/seed. | Fixed (seed 20261009). |
| D7 | The daily screen result was not persisted (Binance did quote in this sample: 1,175 fills across arms). | Persisted to `screen_YYYYMMDD.json`. |
| D8 | Local vs exchange clocks mixed in the 450 ms gate and the 10 s horizon; not measurable. Observed: no fill younger than 450 ms. | Unchanged. |
| D9 | Trade-through fills occur after price already moved against the quote, so edge is a conservative lower bound. | Unchanged (by design). |
| E1 | Seven exit reads (5 events, 13:09:57-13:10:00 UTC) happened 57-60 s late, consistent with a restart or stall; `downtime.csv` is header-only although the pre-registration requires every downtime gap to be recorded. Gross on those rows is -19 bps vs -4.8 elsewhere; effect on pooled means < 0.02 bps. | Not addressed; downtime logging should be checked. |
| E2 | 8-decimal logging quantises mid-based markouts for 11 Binance PEPEUSDT fills (price 4e-6, one tick ~ 25 bps); gross edge (on-tick prices) is unaffected. | Not addressed (minor). |
